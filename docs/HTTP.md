# Local workspace boundary

Run `npm start` with Node 24 or later. The default URL is `http://127.0.0.1:31929/`; `SCOPELINE_PORT` may select another unoccupied port. The launcher binds only to IPv4 loopback. Do not expose this server with a tunnel, reverse proxy, port forwarding or a public listen address. It has no production account login. PayPal Sandbox is disabled by default; explicit [private Sandbox settings](PAYMENTS.md#run-the-sandbox-workflow) enable the real sandbox-only transport and durable private operation ledger.

The browser workspace uses a server-generated random cookie and a separate server-derived owner. Cookie possession isolates anonymous workspaces; it does not identify a real buyer or prove who clicked a checkbox. The cookie is `HttpOnly; SameSite=Strict; Path=/`, with the listening port in its name so two local instances do not replace each other's cookies. The loopback HTTP cookie has no `Secure` attribute. A production deployment would need its own HTTPS/session and identity design rather than forwarding this local server.

## API

All responses have `Cache-Control: no-store`. API errors use `{error:{code,message}}`; private prompts, raw model/provider responses and unexpected diagnostics are not echoed in errors or request logs. All mutations require the exact local Origin, JSON content type and current `X-CSRF-Token`. The server validates Host, rejects cross-site Fetch Metadata except for the two inert checkout-return pages, does not trust forwarded headers and exposes no CORS allowance.

| Route | Behavior |
| --- | --- |
| `GET /api/session` | Create or load an anonymous workspace; return CSRF, immutable catalog/version, restrictions, capability flags, draft, quote, extraction mode, `activity` busy flags and `payment` (null or a safe operation view). `localAi:true` means configured, not healthy or verified. `paypal:true` means explicit Sandbox configuration, not a successful transaction. |
| `POST /api/drafts` | Exactly `{rawBrief,mode:'ai'|'manual'}`. AI uses the real local adapter; only validated extraction creates a draft. Manual mode is an explicit separate choice with no inference and an empty proposal list. Neither mode creates a quote. A successful new draft replaces this workspace's old active draft and quote. |
| `POST /api/drafts/:id/review-preview` | Exactly `{expectedVersion,scope}`. Partial scope is allowed for pure calculation; return missing fields, comparison status, catalog conflicts and changes. Does not save edits or approve anything. |
| `POST /api/drafts/:id/review` | The exact complete [domain review contract](DOMAIN.md). Require all 11 final fields, every original proposal decision, every original conflict resolution and explicit grounding/rights assertions. Save only a valid catalog-compatible complete scope. Invalidate the previous active quote. |
| `POST /api/drafts/:id/quote` | The exact [domain confirmation contract](DOMAIN.md). Current version/digest and explicit scope/price assertions are mandatory. Reconfirmation of the same review returns its existing quote. No payment operation occurs. |
| `POST /api/payments/create` | Exactly `{quoteId}` for the current confirmed quote. The server chooses merchant, amount/currency, owner and return URLs; save intent before a provider POST. Repeated calls return the same operation without a new create POST. |
| `POST /api/payments/:id/reconcile` | Exactly `{}`. Check an owned operation using fixed provider GET routes, never a create/capture retry. |
| `POST /api/payments/:id/capture` | Exactly `{}`. Reverify approval and the current pinned quote, persist capture intent, dispatch once, then independently verify order and capture. Unknown results remain retained. |
| `POST /api/clear` | Exactly `{}`. Reject if a payment is running or unresolved. Otherwise revoke the session, replace book/owner/CSRF/cookie and return an empty workspace. Discard late AI results; preserve completed payment records. |
| `GET /paypal/return`, `GET /paypal/cancel` | Fixed inert page, including cross-site browser navigation. Ignore all query data; no session lookup, approval or capture mutation. |

The client cannot supply owner IDs, raw AI proposals, replacement catalog prices, provider order IDs, return URLs, approval flags or payment-success claims. Unknown and foreign record IDs return the same 404 response. Stale reviews/versions return 409; incomplete/conflicting review data or extra fields returns 422. Only the active draft is accessible; this is not a historical-record API. Payment routes return `{payment:...}` even for state `unknown`; HTTP 200 does not establish completion. See [payment enums, evidence and error codes](PAYMENTS.md#controller-and-api-contract).

## Bounds and races

Briefs are limited to 2,000 JavaScript UTF-16 code units. Request bodies are limited to 32 KiB, with a five-second body deadline and no compressed bodies. Static responses are limited to ordinary top-level HTML/CSS/ESM files under `public/`; project sources and private receipts are outside that surface. CSP disallows inline scripts, remote scripts, frames and embedded objects.

One AI extraction can run across the server at a time, with the adapter's own 90-second deadline and no automatic retry. Each session can start at most two AI calls per minute and 90 API requests per minute. While its extraction is running, that workspace cannot start another draft/review/quote; Clear remains available. Failed extraction preserves the previous stored workspace. It does not silently switch to manual entry.

Sessions expire after 45 minutes without API activity or eight hours total, and the server holds at most 32 sessions. Expiry/Clear/process termination remove reachable in-memory workspace records, while the payment journal remains. A new anonymous session cannot reclaim the previous owner's payment; operator recovery is required after expiry or restart. These are retention boundaries, not secure erasure, removal of local-model memory or cancellation of a provider operation. The old extraction still occupies the global AI slot until completion/timeout; a fresh session may receive 429. `activity.aiBusy` reveals no other session's content. Late AI results cannot create a record after revocation. Closing/reloading a tab alone is not a verified deletion action.

Review and quote mutations are synchronous after bounded body parsing. Requests that finish reading after revocation are rejected. An existing payment operation locks saved review, quote and replacement-draft mutations. In-flight payment work also blocks concurrent payment actions and Clear. The [operation ledger](PAYMENTS.md) pins quote/version/digest/merchant, persists separate request IDs and preserves unknown states; a completed order must be backed by independent matching order and capture GET evidence. Session expiry during provider work withholds the response from the revoked browser without deleting its durable operation. Clear never resets payment idempotency or audit records. Read-only review preview remains available.

The client permits explicit Clear during its pending AI request and ignores superseded response/error/completion handlers. This does not cancel server inference. A lost Clear response triggers one `GET /api/session` reconciliation, not a retry of Clear. If that read also fails, mutations and current-quote claims remain blocked until explicit status refresh succeeds. Same-context refresh retains unsaved controls. These changes postdated the historical 63-check probe and were covered by a separate 47-case controlled suite; neither historical scope proves later browser behavior. See [UI behavior](UI.md).

Fake providers in these suites do not prove actual Sandbox execution. Separately, three distinct real Sandbox flows completed: one manual/API path and two actual desktop-browser AI/review/payment paths. It exercises Host/Origin/CSRF, rejected bodies and extra fields, owner isolation, missing fields, preview, stale review/quote behavior, expiry, global AI serialization and Clear during a pending extraction. Those tests do not run a model, measure model quality, exercise a real browser, authenticate a real person or call PayPal.

A separate one-shot integration run on 2026-10-30 passed 63 checks against this native controller and its then-existing six public files. It checked HTML/CSS/ESM status, MIME and source hashes; CSP/no-store/no-CORS headers; private-path rejection; distinct anonymous sessions and CSRF rejection; one actual local Ollama request; and an independent explicit manual review, quote, scope-change and Clear flow. A three-thumbnail scope produced a fixed USD 45 unpaid quote. Saving a two-thumbnail scope removed the active quote and rejected the previous confirmation version; a newly confirmed quote still used the USD 45 package price. Clear rotated the session/cookie/CSRF, removed its accessible draft/quote and rejected reuse of the old session for a mutation.

That historical synthetic AI brief returned nine expected proposals and exact quotations, with two fields still missing. It stayed unreviewed and created no quote. Exactly one `/api/chat` request was sent; no retry, download or payment call occurred. Its ephemeral loopback server was closed afterward. `tools/flow-probe.mjs` is plan-only unless passed `--run-once`. Public setup and current evidence do not require private development receipts.

These 63 checks are a machine API exercise against that source snapshot. They do not validate actual browser interactions, Clear/Refresh client races, a real person reading or agreeing, production security, PayPal, deployment or overall AI quality. Later source changes are not covered by that historical run. The earlier retained multi-case model probes still have semantic gaps; see [AI findings](AI.md).
